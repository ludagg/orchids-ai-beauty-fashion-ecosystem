## Blocages éventuels
- L'environnement de CI nécessite que toutes les variables d'environnement `NEXT_PUBLIC_*` et de secrets API (ex: Better Auth, Stripe) soient définies pour éviter les échecs de build Next.js. Des variables "dummy" sont configurées pour passer l'étape CI en l'absence de vraies clés.

## Décisions techniques
- L'API de facturation utilise Stripe en mode `subscription`, ce qui est la norme de l'industrie pour les SaaS.
- La page `Billing` a été scindée en un composant serveur (`page.tsx`) pour la sécurité et les requêtes BDD (via Drizzle), et un composant client (`BillingClient.tsx`) pour l'interactivité des boutons, afin de respecter les bonnes pratiques Next.js App Router.
- Le webhook a été étendu plutôt que recréé, pour conserver un point d'entrée unique par lequel Stripe communique de manière sécurisée avec le backend de Rare (anciennement Priisme).

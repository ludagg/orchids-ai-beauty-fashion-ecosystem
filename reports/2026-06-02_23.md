## 4. Blocages éventuels
- L'utilisation locale (tests API) pour l'API Gemini exige qu'une clé d'API valide soit renseignée, sinon l'application utilise une logique métier de repli locale. Ceci est déjà géré mais limite le scope des tests complets si on souhaite interroger l'IA réellement pendant les tests unitaires.

## 5. Décisions techniques prises
- J'ai fait le choix de centraliser le prompt Gemini dans l'API plutôt que côté client, pour ne pas exposer de logique ni de variables d'environnement, et pour croiser directement de façon sécurisée les informations de l'utilisateur avec la base de données.
- J'ai mis en place un système "fallback" si la clé Gemini n'est pas renseignée (pour éviter des crashs pendant le build ou en environnement local partiel).

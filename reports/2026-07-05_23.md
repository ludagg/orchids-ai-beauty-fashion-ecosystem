## Décisions techniques prises et pourquoi
- **`vi.hoisted` pour les mocks** : J'ai utilisé `vi.hoisted` afin d'initialiser les fonctions de `mock` (`vi.fn()`) requises pour le mock de la base de données Drizzle en amont, ce qui évite les erreurs de "ReferenceError: variable is not defined" durant l'exécution de `vi.mock()`.
- **`bun run test` vs `bun test`** : J'ai forcé l'utilisation du script npm de `package.json` (`vitest`) via `bun run test` plutôt que l'exécuteur interne de bun pour le CI. Cela garantit que la configuration `.vitest.config.ts` et les plugins spécifiques sont bien chargés.

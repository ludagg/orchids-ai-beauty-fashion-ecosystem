## 4. Blocages éventuels
- Drizzle a levé quelques avertissements avec l'utilisation de typages `any` et avec le typage incomplet côté TypeScript lors des mises à jour rapides, mais la base de données est synchronisée avec `drizzle-kit push`.
- L'essayage AR est pour l'instant un MVP visuel qui lance la caméra ; la superposition réelle de vêtements en 3D nécessitera un moteur de rendu plus poussé (ex. Three.js / TensorFlow.js) ou une API tierce spécialisée.

## 5. Décisions techniques prises
- Utilisation de `navigator.mediaDevices.getUserMedia` pour l'AR Try-On pour un accès rapide à la caméra avec des éléments de superposition statiques pour un MVP immédiat.
- Ajout d'un algorithme statique ("fallback") dans l'API AI Fit Check pour s'assurer que les utilisateurs reçoivent toujours une suggestion de taille même si l'API Gemini n'est pas configurée ou échoue.
- Modification de la structure de l'utilisateur via Better Auth (`additionalFields`) pour éviter d'avoir une table séparée pour les mensurations, simplifiant la gestion des données utilisateur.

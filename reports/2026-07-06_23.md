## Ce que j'ai fait ce run
- **Fonctionnalité manquante (Parrainage)** : J'ai conçu et implémenté l'ensemble de la fonctionnalité de parrainage (referral) pour le système de fidélité.
- **Mise à jour du schéma de base de données** : Ajout des colonnes `referralCode` et `referredById` à la table `users`.
- **Configuration Auth** : Mise à jour de la configuration de Better Auth pour exposer et enregistrer les nouveaux champs additionnels.
- **Backend API** : Création des routes `GET` et `POST` dans `/api/loyalty/referral` permettant de générer automatiquement un code unique par utilisateur, de récupérer les statistiques de parrainage, de valider le code d'un ami et d'attribuer les points correspondants via le `LoyaltyEngine` (500 pour le parrain, 200 pour le filleul).
- **Frontend** : Développement du composant React `ReferralsCard` intégré dans le dashboard de fidélité permettant de partager son code et de saisir un code de parrainage.
- **Tests** : J'ai ajouté des tests unitaires (`src/app/api/loyalty/referral/route.test.ts`) simulant les appels avec Vitest afin de s'assurer du bon fonctionnement des cas normaux et de l'interception des comportements anormaux (ex: un utilisateur qui essaie d'utiliser son propre code).

## Blocages éventuels
- L'intégration de la base de données et du cache dans les tests Vitest nécessite la création de nombreux mocks complexes (`vi.mock('@/lib/db')`), ce qui peut rendre les tests fragiles si la structure des requêtes Drizzle ORM évolue (surtout lors de l'utilisation des appels chaînés comme `select().from().where()`).

## Décisions techniques prises
- **Génération des codes de parrainage** : Plutôt que de les créer à la volée lors de l'inscription pour chaque utilisateur et surcharger le processus, j'ai opté pour une génération "lazy" (c'est-à-dire lors de la première consultation du dashboard ou du premier appel à l'API) en utilisant les trois premières lettres du prénom combinées à une chaîne aléatoire (via `nanoid(6)`).
- **Système de récompenses** : J'ai réutilisé directement le `LoyaltyEngine.addPoints` existant, en introduisant le type `referral_bonus`, ce qui permet au système de fidélité d'historiser automatiquement la transaction sans logic métier redondante.
- **Stockage de l'affiliation** : Enregistrer uniquement le `referredById` suffit pour compter le nombre de filleuls (`count` via un simple `SELECT`) sans nécessiter la création d'une nouvelle table de jointure.
